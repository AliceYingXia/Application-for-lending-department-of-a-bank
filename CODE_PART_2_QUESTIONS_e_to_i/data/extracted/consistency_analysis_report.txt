Cost-to-income is the worst-performing metric — not a single company passes
the consistency test. The failure mode is identical across all 9 companies:
Gemini randomly expresses the ratio either as a decimal fraction (e.g., 0.8454)
or as a percentage (e.g., 84.54). In most runs one form dominates, but one or
two rogue runs flip to the other scale, producing catastrophically high CV
values (~1.2 to 2.7).

Observed values per company:

  Alibaba_2024
    Decimal runs (×7): 0.8454, 0.8454, 0.88
    Percentage runs (×3): 88.0, 84.54 — CV = 1.905

  EM_2024
    Decimal runs (×9): ~0.8468
    Percentage run (×1): 84.68 — CV = 2.725

  GM_2023
    Decimal runs (×5): 0.9459–0.946
    Percentage runs (×5): 94.59 — CV = 1.195

  Google_2024
    Decimal runs (×9): 0.6789
    Percentage run (×1): 67.89 — CV = 2.725

  JPM_2024
    Decimal runs (×5): ~0.517
    Percentage runs (×5): 51.7 — CV = 1.195

  LVMH_2024
    Mixed: 0.77–0.78 (×4), 44.74 (×1), 76.92 (×2), 77.7 (×1) — CV = 1.232
    (LVMH has additional ambiguity in what "cost" to use)

  Meta_2024
    Decimal runs (×9): 0.5782
    Percentage run (×1): 57.82 — CV = 2.725

  Tencent_2024
    Decimal runs (×8): 0.471–0.974
    Percentage run (×1): 47.1 — CV = 2.666

  Volkswagen_2024
    Multiple decimal forms (×6): 0.817–0.944
    Percentage forms (×4): 81.68–81.69 — CV = 0.802

Pattern: The underlying ratio value itself is largely consistent (~84% for
Alibaba, ~67% for Google, ~52% for JPM, etc.) — the disagreement is purely
in how that value is expressed. This is a unit ambiguity problem, not a
data-extraction problem.

Root cause: The prompt does not specify whether cost-to-income should be
expressed as a decimal ratio or a percentage. Gemini independently decides
each time, and at temperature 0.7 it occasionally switches conventions.

Recommendation: Add explicit unit instruction to the prompt:
  "Express cost-to-income ratio as a percentage (0–100 scale), e.g. 67.89
   for 67.89%."
This single change should fix all 9 companies simultaneously.

This metric has the most missing data. EBITDA requires Depreciation &
Amortization (D&A), which is typically disclosed on the cash flow statement
or in footnotes — not on the income statement or balance sheet pages provided
to Gemini. When D&A is absent, Gemini cannot compute EBITDA and returns null.

EM_2024 (the only fully consistent result) is exceptional: EM's annual report
appears to present EBITDA explicitly on the income statement pages, or D&A
is visible on the extracted pages, allowing consistent computation.

For Alibaba, GM, JPM, and Meta: the handful of successful runs likely caught
D&A values mentioned incidentally on the income statement (e.g., in a
combined statement or footnote reference), while most runs found them absent.

For Google, LVMH, Tencent, and Volkswagen: no runs succeeded at all.

Recommendation: To reliably compute Debt/EBITDA, extract and provide the
cash flow statement pages (specifically the operating section showing D&A
add-back) in addition to income statement and balance sheet pages. This is
a data-availability issue, not a model-quality issue.

════════════════════════════════════════════════════════════════════════════════

The inconsistencies observed fall into five distinct root-cause categories:

  Category A — Unit / Scale Ambiguity (fixable with prompt change)
  ─────────────────────────────────────────────────────────────────
  Affected metrics: Cost-to-Income (all 9 companies), Debt/Assets (GM),
                    Debt/Capital (GM, JPM)
  Pattern: Gemini returns the same underlying value but alternates between
           expressing it as a decimal (0.9459) or percentage (94.59).
  Fix: Explicitly specify the unit in the prompt. Example:
       "Express cost-to-income as a percentage on a 0–100 scale."
       "Express Debt/Assets as a decimal (0–1 range)."

  Category B — Debt Definition Ambiguity (fixable with prompt change)
  ─────────────────────────────────────────────────────────────────────
  Affected companies: LVMH (D/E, D/A, D/Capital), JPM (all leverage ratios)
  Pattern: Gemini finds two valid debt figures — one narrower (financial
           debt only) and one broader (including leases or deposits).
  Fix: Specify "total financial debt = short-term borrowings + current
       portion of LTD + long-term debt, excluding leases and trade payables."

  Category C — Structural Inapplicability (requires metric redesign)
  ────────────────────────────────────────────────────────────────────
  Affected: JPM (Quick Ratio, D/E, D/A, D/Capital, Debt/EBITDA, Interest Cov.)
            GM, Volkswagen (Quick Ratio, Interest Coverage)
  Pattern: Standard corporate ratios do not apply to financial institutions
           or automotive companies with captive finance arms. Gemini produces
           variable results because no single correct answer exists.
  Fix: Use sector-appropriate metrics for banks and auto-finance companies.

  Category D — Data Availability (fixable by providing more pages)
  ─────────────────────────────────────────────────────────────────
  Affected metrics: Debt/EBITDA (5 companies null or sparse), Interest
                    Coverage (Google, Volkswagen), Quick Ratio (Tencent,
                    Volkswagen)
  Pattern: Required line items (D&A, interest expense, current liabilities)
           are not present on the extracted income statement / balance sheet
           pages.
  Fix: Include cash flow statement pages for Debt/EBITDA; include notes
       pages for interest expense; verify balance sheet coverage.

  Category E — Minor Outlier / Single-Run Anomaly (low severity)
  ──────────────────────────────────────────────────────────────────
  Affected: Alibaba (Quick Ratio, Interest Cov.), LVMH (Interest Cov.),
            EM (Interest Cov.), Tencent (Interest Cov.), GM (Net Income)
  Pattern: 9 of 10 runs agree; 1 run returns a slightly different value due
           to a legitimate but alternative line-item choice.
  Fix: Reduce temperature to 0.3 or 0.0 for more deterministic extraction.
